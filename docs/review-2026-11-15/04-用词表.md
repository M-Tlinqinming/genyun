# 04 用词表与补画划线（建议稿，2026-11-16）

这份稿子对应问题清单第七节和第六节，到确认点 2 跟决定包一起过。

- **第一部分是用词表。** 39 组，每组给一个建议用词。你只标不同意的，没标的就按建议，在各端改稿时统一替换。
- **第二部分是补画划线。** 第六节 31 处没画全的状态，我分成「交开发前必须有」和「以后补」两类。你确认这条线划得对不对。

几条已经定了的规矩，这里直接沿用，不再问：

- 全站叫「专家」（11-04 定）。
- 找客户由客服联系（11-09 定）。
- 「任务」「复制缺项清单」这两个叫法不变（11-13 定）。
- 收费按「编制次数」算（11-05 定）。

## 一、用词表

### 1. 人、单位、工作区

| 编号 | 说的是什么 | 建议用词 | 理由 |
|---|---|---|---|
| 7.1 | 客户所在的单位 | **组织**。客户端页面叫「组织管理」，下面分「组织资料」「成员与权限」；运营端叫「客户组织」 | 买服务的有安全咨询机构，也有企业自己。「机构」套不到企业身上，「组织」两边都能用。⚠ 这一组改动面最大，请你特别看一眼 |
| 7.2 | 称呼对方的单位 | 不用「贵机构」「贵单位」「本机构」。要么写「您的组织」，要么干脆省掉主语 | 产品里的口气平一点 |
| 7.3 | 三个工作区 | 客户工作台、专家工作台、运营工作台。切换器显示组织名或「耕云专家」「耕云运营」；顶栏左边不再写工作区名 | 跟 3.3 一起改：专家端要出现「专家」两个字 |
| 7.4 | 账号 | **账号**。个人设置页叫「账号设置」 | 「账户」容易想成钱 |
| 7.5 | 找回密码 | 登录页链接写「忘记密码」，进去以后整个流程叫「重设密码」 | 跟常见产品一致 |
| 7.6 | 客户的管理员 | **组织管理员**。和普通成员对照时，写「管理员 / 成员」 | 跟着 7.1 改 |

| 编号 | 说的是什么 | 建议用词 | 理由 |

| 7.9 | 第一份文档 | 界面上一律写「**应急预案**」。标准全称「生产安全事故应急预案」只用在文档封面和官网 | 「综合预案」是这份文档里的一部分，不能拿来叫整份 |

### 5. 官网（7.28、7.39）

官网这一轮不在范围里。只先定词：

- 「登录」
- 「预约演示」
- 「编制」，不写「生成」

导航名和页面标题对不上的问题、文案板和页面不一致的地方（7.39），放到确认点 6 跟官网一起看。

### 6. 口吻和格式

| 编号 | 建议 |
|---|---|
| 7.29 人称 | 产品里称呼对方一律用「**您**」。说明板上用「我」写的话不进产品 |
| 7.30 「待…」 | 专家要做的写「**待您补充**」；客户没填的写「**客户未填**」。其余五种说法都不用了 |
| 7.31 紫色来源标签 | 只留两种字样：「**您已修改**」「**您填写**」。客户表格带过来的内容挂「客户表格」标签，不挂紫色 |
| 7.32 日期 | 当天和前一天写「今天 10:40」「昨天 10:40」；今年其他日子写「11 月 16 日 10:40」；不是今年的写「2025 年 11 月 16 日」。只要日期时去掉时分 |
| 7.33 人名 | 姓名和角色分两行，比如「林某」下面一行写「组织管理员」。自己那一行后面加「（您）」 |
| 7.34 打码 | 手机号写「138 **** 2601」，只遮中间四位。邮箱不打码。自己的号码不打码 |
| 7.35 引号 | 一律用「」 |
| 7.36 系统腔 | 「可访问性」改成「能看哪些企业」；「发布请求已受理」改成「正在发布」；「未形成交付」改成「这次没有发布成功」；「全部可见任务」改成「全部任务」；「后台」改成「运营端」；「同批交付」改成「一起交付」；「选择空间不会增加账户权限」直接删掉 |
| 7.37 设计备注 | 产品稿上的设计备注、开发说明全部删掉。需要留的挪到说明板上 |
| 7.38 不通的句子 | 改稿时逐句重写，在各端验收的改动说明里列出原句和新句 |

## 二、补画划线（第六节 31 处）

划线的标准有两条：

- **交开发前必须有。** 主线上一定会碰到的空的、正在进行的、出错的样子，加上已经有入口、点了却没有去处的地方。
- **以后补。** 低频的情况、流程还没定的，或者这一轮不在范围里的。这类的入口先从稿上拿掉或者置灰，免得开发做出一个点了没反应的按钮。

### 交开发前必须有（19 处）

| 端 | 编号 |
|---|---|
| 客户端 | 6.8 第一次用的空状态；6.9 撤回；6.10 上传中、上传失败；6.11 已传的图纸和照片；6.12「这张图我们没有」的确认和改回；6.13 点开「查看是哪 7 项」「查看客服二维码」以后；6.14 删除任务的确认；6.15 新建企业、新建任务的校验报错 |
| 专家端 | 6.6 查看客户原表；6.17 专家自己的「查看缺项」；6.18 查看原图、代客户上传；6.19 复制缺项清单以后；6.20 外部联系方式填写；6.21 添加组员、工序、危险源的弹层，校验报错，自动保存失败；6.22 Word 预览、处理记录、第 2、3 份文档的核对页、未保存提示；6.23 新旧对照只处理了一部分、核对到一半、V2 发布中和发布失败 |
| 运营端 | 6.25 邀请、停用、移交、改派的弹窗；6.26 开通以后的结果 |
| 两端都有 | 6.4 只做两屏手机稿：客户成果页（客户可能在手机上点交付邮件）和登录页 |

6.4 里登录页在 10 页。10 页这一轮本来只修画错，这一屏是例外，因为点开邮件以后第一眼就是它。

### 以后补（12 处）

| 编号 | 先怎么处理 |
|---|---|
| 6.1 客户端「我的反馈」 | 入口先不放；反馈照现在的做法走客服 |
| 6.2 运营端「操作日志」 | 运营概览里的「查看全部操作记录」先拿掉，只留「最近操作」那张卡 |
| 6.3 服务到期以后 | 合同一年，第一批客户明年才会到期，到时候再画 |
| 6.5 专家改稿时的自动检查和待补充清单 | 牵涉到规则怎么定，单独再议 |
| 6.7 客户反馈转给专家以后 | 跟 6.1 一起做 |
| 6.16 企业详情页里的「任务」「成果文档」页签 | 页签先拿掉，企业详情只留资料 |
| 6.24 运营端客户组织、知识库的其余页签 | 只画已经有内容的页签，其余先不放 |
| 6.27–6.30 登录、邀请、重设密码、预约演示的各种状态 | 10 页不在这一轮范围里；开发时先照 Ant Design 默认的报错样子做 |
| 6.31 官网上有入口没去处的地方 | 跟官网一起放到确认点 6 |

## 三、要你看的

1. 用词表里只标你不同意的。最要紧的是 7.1：客户的单位到底叫「组织」还是「机构」。
2. 补画这条线划得对不对：「必须有」19 处，「以后补」12 处，后者先把入口拿掉。
