## 每个区块的五步

1. 走一遍现有产品：Martin 扮演客户，从登录走到提交。我记下卡住、犹豫、看不懂的地方，并把真实截图放到对应画板旁边。（只在用户端前做一次）
2. 字段倒推：从生成和导出的代码往回查，每个客户字段标「必需 / 有用 / 没人用」。
3. 整条路一块板：先砍步骤和状态，只动结构，不动视觉。Martin 逐条拍板。
4. 逐页细化：v2 稿放在原画板旁边，不覆盖原稿。每页检查同一份清单：一个主任务、一个主按钮、次要信息折叠、只用业务语言、同一件事全站一种叫法。
5. 定稿后开发：开发清单交给 Agent 实现，另一个 Agent 审查，CI 绿了合并。Martin 在产品里重走一遍验收。开发进行时，开始下一个区块的第 1–3 步。

### 用户端

- 2026-11-04：工作流定下，分支建好；后台开始做字段倒推，同时准备走查环境。
- 2026-11-04：字段倒推完成，见 `docs/design-v2-user-fields.md`（约 49 必需、31 有用、7 没人用、4 待确认）。
- 2026-11-05：走查完成（惠州市深同跃实业，从登录走到提交）。Martin 在 Paper 30 页留了 23 条批注，归成 7 类：
  1. 选中状态和视觉反馈弱：「您想怎么开始」两张卡片、人员两种填写方式、提交后的状态标签。
  2. 「稍后补」太多：大量内容推到提交后，客户和专家来回沟通，最后堆成待补清单。这是最大的结构问题。
  3. 要上传后自动识别并填写：营业执照（OCR，必须做）；花名册和设备、原辅材料，从 Excel 或 Word 识别。
  4. 客户看不懂、或者不该问的字段：所属行业（生成没用到）、消防验收资料、建(构)筑物一览、气瓶。需要问号提示，或者直接删。
  5. 布局：设备和材料改用表格组件；清理灰色字体；手动填写看不到注册资本、登记机关。
  6. 流程死路：选了「上传已有资料」后回不到引导填写；任务不能删除。
  7. 平台问题：以后加隐患排查、安全生产 PPT 等模块，放在哪里、怎么搭。
  - 工艺流程：删掉「一句话描述」；页面指引要更清楚，免得客户以为已经可以生成。Word 里的多产品工艺流程图，先记作疑问。
  - 应急资源页：问号提示要改成「咨询专家」。
  - 下一步：画 Paper「用户端 · 全流程 v2」，结构上怎么砍（先砍「稍后补」）由 Martin 逐条拍板。
