## 1. 第一期范围（方案 B）

**原则**：编制主线全部线上化；商务（报价、签合同、收款、开票）全部线下，先签约付款，运营再开通系统。外部审核（备案）不卡开发进度。

### 1.1 线上完成

- 企业两种开始方式都做：**按提示填写（5 步）**、**上传已有资料**，之后进入同一条审核与交付流程。
- AI 起草 → 注册安全工程师整理、编制、Word 校对、补件、直接联系客户补充 → 发布 → 客户直接下载三份 Word（已签约付款，系统内不再有付款环节）。
- 运营端：开通组织（登记合同信息）与邀请首位管理员、分配专业人员（负责专家）、超时兜底、上门工单、知识库、反馈受理。
- 官网（独立静态站）。

### 1.2 第一期人工处理

| 环节 | 第一期 | 以后 |
|---|---|---|
| 报价与合同 | 线下洽谈报价（按企业规模、行业或套餐），签合同 | 价格稳定后做价目表 |
| 收款 | 线下对公转账，到账后运营开通组织；系统不记录金额 | 视需要再议在线支付 |
| 发票 | 财务线下开数电票并直接发给客户，系统不处理 | 视需要再议 |
| 合同范围 | 运营开通时登记：合同编号、服务范围（如「编制 1 家企业」「年度 N 家」）、合同有效期、已签合同原件（必传，仅 PDF，双方签章扫描件，≤ 20 MB，存对象存储，仅运营可见）、「合同款已到账」确认；原件未上传或未确认到账不能开通。第一期不做额度拦截，超出范围由运营人工判断 | 按额度自动提醒 |

## 2. 从设计到代码

- **不用 Ant Design Pro 等后台模板**，在 Ant Design 6 上自建框架，通用功能用成熟开源库。
  - 原因：ProComponents 正式版（2.8.10）只支持 antd 5，支持 antd 6 的 3.x 还是 beta（3.1.15-7）；模板的默认布局和外观与设计不符，改造成本高于自建。（2026-10-23 查 npm）
  - 原则：耕云独有的业务逻辑（任务状态、合同有效期、权限、补件流程）自己写；页面跳转、数据加载、表单校验等通用功能用成熟库。
- **开发顺序**：
  1. 设计 token → Ant Design 主题配置；
  2. 通用组件（顶栏 64 / 侧栏 224 框架、状态标签、来源标签、分步向导、右侧说明栏、上传区）；
  3. 逐页开发。
- **每页的做法**：通过 Paper MCP（`get_jsx` / `get_computed_styles` / token）取精确值，不从截图估算；开发后截图，与 Paper 并排比对并修正。
- **设计依据**：Paper 10–16 页高保真；20–22 线框只补高保真未覆盖的部分；90–97 归档不用。
- **颜色 token**：只用 `gy-v1-*`（产品后台）和 `gy-brand-*`（官网）。旧的绿色 token（`--color-primary` #2D7A52 等）**废弃**。
- **没有高保真的新页面**（开通组织时的合同信息字段）：按现有设计系统直接开发，开发后验收，不再补高保真。

## 3. 技术架构

| 部分 | 选型 | 理由 |
|---|---|---|
| 后台前端 | React + TypeScript + Ant Design 6，三端（客户 / 专家 / 运营）放在一个单页应用里，登录后按身份进入不同工作区 | 设计基于 antd 6；三端共用主题和组件 |
| 官网 | 独立静态站 | 视觉与后台不同；需要被搜索引擎收录、打开快；备案时要有可访问的官网 |
| 后端 | Node.js + TypeScript，NestJS | 复用旧仓库资产；前后端共用一套字段规则；权限检查有统一位置 |
| 耗时任务 | Redis + 任务队列（AI 起草、Word 生成在后台执行，页面显示进度，完成后站内 + 邮件通知） | 避免请求超时 |
| 数据库 | PostgreSQL（阿里云托管版） | 旧仓库同库，表结构可参考；备份和高可用由云厂商负责 |
| 文件 | 阿里云对象存储，私有读写，服务器端加密；下载用短时效签名链接 | 文件没有公开地址 |
| Word 生成 | 沿用旧仓库流程：Markdown 模板 → Pandoc + Word 样式模板 → 后处理；流程图用 mermaid 渲染 | Martin 确认旧格式可接受 |
| 部署 | Docker 镜像（含 Pandoc、mermaid 渲染工具） | 不绑定云厂商，可直接迁移 |

### 3.3 实现时补充的选型（M0，2026-10-23）

| 事项 | 选择 | 理由 |
|---|---|---|
| 仓库结构 | npm workspaces：`apps/web`、`apps/api`、`packages/shared`（前后端共用的规则） | 不需要额外安装工具 |
| 数据库访问 | Drizzle ORM；本机开发与自动测试用 PGlite（进程内的 PostgreSQL），预览与正式环境连真实 PostgreSQL | 本机和 CI 不需要安装数据库，测试跑的是真实 PostgreSQL 语法 |
| 登录会话 | 随机令牌放在 httpOnly cookie，数据库只存哈希；有效期 7 天；密码用 Argon2 | 浏览器脚本读不到令牌；数据库泄露也拿不到可用令牌 |
| 登录限流 | express-rate-limit，同一 IP 每分钟 10 次 | `@nestjs/throttler` 是 CommonJS 包，和 ESM 版 NestJS 12 同时加载会出现两份内部实例，无法使用 |
| 部署形态 | 一个 Docker 容器同时提供前端页面和后端接口 | 第一期只有一台服务器，少一层 Nginx 配置 |
| 字体 | 界面用本机字体（Noto Sans SC → Segoe UI → 微软雅黑），只有 Logo 字标随应用打包 | 设计系统要求「无外部字体下载」；国内访问不到 Google Fonts |
| 文件存储（2026-10-27） | 本机开发与测试存磁盘；接口按阿里云对象存储设计，预览与正式环境只换配置 | 开发阶段不依赖云账号；切换时不改业务代码 |
| 资料清单规则（2026-10-27） | 19 项定义、状态校验、提交检查放在 `packages/shared/src/checklist`，E1–E4 字段放 `packages/shared/src/profile` | 前后端共用同一套规则 |
| 合同有效期（2026-10-27） | 组织只存一个合同有效期（开始日、到期日，按北京时间、起止日都算在内），取代原「年度服务到期日」；有效期内才能新建任务，到期前 30 天提醒也按它算。合同编号、服务范围在 M3 登记页面时再加 | 两者规则相同，只保留一个日期避免不一致 |
| 任务编号（2026-10-27） | 全平台按年流水 `GY-2026-001`，超过 999 自然变长；同一家企业同一种业务只能有一个没结束的任务（数据库唯一约束保证） | 专家与运营在任务中心看到的编号不重复，电话沟通报编号即可找到 |
| 企业、任务、资料项（2026-10-27） | 任务冗余存所属组织，权限查询不连企业表；资料项每个任务每项一行，客户没回答的项没有记录；「已提供」「没有」由后台记录确认人和时间。运营可查看但不替客户建档、建任务或填资料；专家只能通过分派给自己的任务查看 | 权限判断集中在 `apps/api/src/auth/access.ts` |

**设计稿差异记录**：设计系统规定控件边框为 #89909C（对比度达标），但部分高保真页面的输入框按 Ant Design 默认的 #D9D9D9 绘制，「忘记密码」链接也用了默认蓝 #1677FF。实现以设计系统为准。

### 3.5 资料清单与数据模型变更（2026-10-26）

依据业主实际使用的《生产安全应急预案资料清单》两个版本，客户资料整理为 6 类 19 项。采集规则以 Paper 03 页 FM02 为准，字段归属以 FM01 为准；客户状态的界面规范见 04 页 DS 04B。旧仓库 zod 规格需要按下表扩展，扩展后的规则放在 `packages/shared`，前后端共用。

**资料项状态（每一项都有，不分来源）**

| 字段 | 取值 | 说明 |
|---|---|---|
| `status` | `provided` / `none` / `later` / `photo_for_expert` | 客户端四种状态；取消通用的「不确定」 |
| `confirmedBy` / `confirmedAt` | 用户 ID / 时间 | `provided`（直接填写时）和 `none` 必填 |
| `expertJudgement` | `pending` / `yes` / `no` + 判定人、时间 | 专家判断项与 `photo_for_expert` 使用；判定为无不需填写理由 |
| `required` | `start` / `before_delivery` / `system` | 开始编制必需 / 交付前补齐 / 耕云代办；`start` 级不允许 `later` |

- 专业判断（是否危化品、是否属于压力容器或压力管道、耐火等级）不作为客户字段，只存在专家侧。
- `later` 与「待专家电话联系」累计超过 5 项时，提交页和任务页提示预约上门。
- 不收取权属类文件（土地证、房产证、规划许可等）：占地面积、建筑面积、层数一律由客户直接填写，不提供这类文件的上传入口。
- 客户沟通（2026-10-26 修订，取代 10-23「客服统一拨打」）：每个任务一位负责专家（任务字段 `assignedExpertId`），客户页显示负责专家姓名与身份，不显示专家电话。专家联系客户两种方式：在任务里发「补充请求」（进入客户待补清单，系统自动邮件 + 站内提醒），或自己打电话后填写联系结果（已问清 / 客户稍后补 / 未接通）与回答。所有联系写入任务联系记录（客户不可见）。客户点「请专家电话联系」后，专家 2 个工作日内无联系记录的任务进入运营「超时兜底」，运营可提醒专家、改派专家（整理内容与联系记录随任务转移），或先致电客户说明进度，但不代专家问专业问题。第一期专家用自己的电话拨打，接受来电显示专家号码；隐私号（虚拟中间号）以后再议。

## 4. 合规与部署

### 4.1 已定

- **云厂商**：阿里云（已购买），华南机房（深圳或广州）。
- **域名**：`genyun.net.cn`（已购买）。正式环境用 `genyun.net.cn`，预览环境用 `staging.genyun.net.cn`，发信用子域名（如 `mail.genyun.net.cn`）。
- **大模型**：只用已在网信办备案的国产大模型，通过阿里云百炼调用；上线前在网信办公布的已备案清单里核对模型名称和备案号。选择承诺不用客户数据训练的服务；发送前去掉不必要的个人信息。
- **AI 的定位**：AI 只做专家的内部起草工具，客户看不到未经审核的 AI 稿。系统记录每份文件使用的模型和审核的注安师。
- **AI 标识**：交付的 Word **正文不加**可见的 AI 说明，只在文件元数据中写入「AI 辅助起草、注册安全工程师审核」。如网信办答复要求可见标识，再调整。
- **安全建设**：按等保二级要求建设，包括加密存储、全程 HTTPS、操作日志、定期备份、最小权限。正式定级备案和测评安排在上线后。
- **邮件**：阿里云邮件推送，用子域名发信，配置 SPF、DKIM、DMARC。免费额度为每账号 2000 封、每天最多免费 200 封，初始每日上限 2000 封。

### 4.4 费用粗估（开发前用阿里云价格计算器出正式报价单）

- 第一期：1 台 2 核 4G 服务器 + 基础版 PostgreSQL + 小规格 Redis + 对象存储 + 带宽，约每月几百到一千多元。
- 备案完成前的香港预览服务器：每月一笔额外费用，备案完成后退订。
- 等保测评、外部安全审查：向机构询价。

## 5. 收款与发票

> 2026-10-26 修订：取代原「提交不收费、审核通过后确认费用再付款」。改为先签约付款、再开通系统，系统内不做付款与开票。

### 5.1 先签约付款，再开通

```
线下：洽谈 → 报价 → 签合同 → 对公转账 → 财务开票（线下发给客户）
线上：运营确认到账后开通组织（登记合同编号、服务范围、到期日）并邀请首位管理员
  → 客户建档、提交
  → 专家整理、编制、审核
  → 发布 → 客户直接下载三份 Word
  → 修订期（交付后 3 天内，因事实变化可免费修订 2 次）
```

- 任务没有费用状态；组织在合同有效期内即可创建任务、下载成果。
- 合同到期：不能新建任务，已交付成果仍可查看和下载（与年度服务到期规则一致）。
- 合同信息只有运营可见；客户在组织资料里只看到服务范围与到期日。

### 5.2 发票

- 财务线下在电子发票服务平台开具数电票并直接发给客户，系统不记录、不上传。

### 5.3 以后如需在线支付的前提

- **微信支付（电脑网页扫码）**：企业可申请；需要已认证的服务号（或已认证的小程序、App）绑定商户号。建议提前注册并认证公司服务号。
- **支付宝（电脑网站支付）**：第三方资料显示要求网站已完成企业 ICP 备案。⚠️ 未能核实支付宝官方文档。
- 两家手续费以商户后台为准。⚠️ 未查到官方费率。

## 6. 工作方式

### 6.1 代码管理

- 代码托管在 GitHub 私有仓库。`main` = 正式线上版本；每块功能在独立分支开发，通过检查后再合并。
- **铁律**：真实客户数据和密钥（数据库、大模型、邮件等）绝不进仓库，统一存放在服务器配置中。

### 6.2 三道质量关

1. **自动测试**（不通过不能合并）：业务规则（字段校验、决策引擎、合同有效期）；越权测试；主线全流程浏览器测试（开通组织 → 提交 → 审核 → 发布 → 下载）。
2. **代码审查**：每个分支合并前做独立审查；**上线前请外部资深工程师做一次安全审查**（Martin 已同意安排预算），见 6.5。
3. **Martin 验收**：预览链接 + 设计稿与实际页面的并排截图 + 用业务语言写的检查清单。

### 6.3 环境

| 时期 | 预览环境 | 正式环境 |
|---|---|---|
| ICP 备案完成前 | 阿里云香港小服务器，只用虚构样例数据 | 无 |
| ICP 备案完成后 | `staging.genyun.net.cn`（境内，独立数据库） | `genyun.net.cn` |

### 6.4 里程碑

| 里程碑 | 内容 | 验收物 |
|---|---|---|
| M0 地基 | 主题、通用组件、登录、三端框架、自动部署 | 能登录，看到三个工作区框架 |
| M1 客户提交 | 建档、两种开始方式、检查与提交 | 用样例企业从头填到提交 |
| M2 专家处理 | 任务中心、整理、AI 起草、编制、Word 校对、补件、联系客户与联系记录、发布；客户成果文档页 | 第一份系统生成的三件套 Word |
| M3 运营 | 组织开通与合同登记、邀请、分派与超时兜底、上门工单、知识库、反馈；客户组织管理页（成员、企业分配、年度服务） | 一个新客户从开通走到提交、下载 |
| M4 官网与上线 | 官网、发信配置、外部安全审查、正式环境、监控与备份 | 正式上线 |

- M2 排在 M3 前：AI 起草和 Word 生成技术风险最大，要尽早暴露问题。
- ICP 备案和 4.3 的政策咨询与 M0 同时启动，最晚在 M3 结束前要有结果。

### 6.5 外部安全审查范围（供询价）

- 登录、会话、密码重设、邀请链接（含过期处理）；
- 多组织数据隔离与角色权限（客户组织 / 专业人员 / 运营管理员），越权访问测试；
- 文件上传与下载（类型校验、私有存储、签名链接时效）；
- 合同有效期与组织权限能否被绕过（到期后新建任务、越权下载）；
- 密钥管理、日志与备份；
- 交付形式：问题清单 + 风险等级 + 复测。
