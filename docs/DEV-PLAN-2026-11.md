# 开发计划 · 2026-11

> 2026-11-20 设计定稿后写。页面以 Paper 10–16 页为准，业务规则以 `CLAUDE.md` 和 `docs/design-v2.md` 为准。**各项状态只在 `docs/PROGRESS.md`「总表」里记**，本文只放计划和技术安排。

## 一、先说结论

- **11-30 前做到：主线在本机能从头走到尾。**
  - 客户：新建任务 → 下载资料模板 → 填好上传、传图纸 → 系统查 20 项必填，缺了指出是哪张表哪一行 → 提交（专家开始核对前可以撤回一次）→ 看进度 → 下载整套 Word。
  - 专家：任务中心 → 五步核对 → 生成初稿 → 核对定稿 → 定稿并交付 → 需要时重新打开、再交付。交付邮件进本机的模拟发件箱。
  - 运营：开通组织（录合同、到账、次数）→ 调整次数、登记续约 → 派专家。按交付扣次数，用完锁成果，续约或加购后自动放开。
- **工作量：** 16 个开发项，约 22 天工作量，分三条线并行。11-21 到 11-27 做完，11-28、29 跑回归测试、修问题，11-30 你从头走一遍。
- **放到 12 月第一周（约 8 天）：** 专家自己注册入驻、专家库审核上架、客户提交时选专家、知识库五类资料、其余页面换新样式、官网条款页。
  - 12 月之前的过渡做法：专家由运营在「内部账号」里邀请；客户提交时，编制专家一栏只显示「由耕云安排」；知识库沿用现在的属地机构页。
- **进度落后时，按这个顺序往后挪：** 企业与组织管理换样式（K8）→ 核对定稿换样式（K15）→ 运营概览 → 重新打开后再交付。主线不挪。
- **你要做的：** 每端做完约你在本机走一遍，每次 20–30 分钟（见第九节）。其他由我安排。

## 二、怎么做

- **分工：** 我拆开发项、写任务说明、审结果。每个开发项由一个子代理写代码（Opus 5.5，中等强度），另一个子代理只读审查。我看过审查结论和页面截图后开合并请求，**CI 全绿才合并**。
- **三个工作区并行**，你本机的 `genyun` 一直停在 main，只在你不测试时才拉新代码：

| 线 | 工作区 | 浏览器测试端口（API / 页面） |
|---|---|---|
| A 客户线 | `genyun-w1` | 3100 / 5174 |
| B 专家线 | `genyun-w2` | 3200 / 5274 |
| C 运营与计费线 | `genyun-w3` | 3300 / 5374 |

- **页面以 Paper 为准：** 取值用 `get_jsx` / `get_computed_styles`，不从截图估。细节和设计稿不一样就改代码；要动结构、流程或文案先问你；差异记进 `docs/DESIGN-DIFF.md`。
- **数据只加不删（总表 P3）：** 迁移只加表、加字段、放宽约束，不删已有数据。旧流程的表保留不动。
- **防冲突：** 数据库迁移只在 K3 写，菜单只在 K2 改。三条线开工后谁要改数据库，先报给我统一排。
- **不部署：** 香港测试服等你开口再部署；部署前先在本机查迁移和演示数据。

**K14 按次扣费与提醒**（design-v2「计费」、11 页 C01·S02、16 页次数说明）
